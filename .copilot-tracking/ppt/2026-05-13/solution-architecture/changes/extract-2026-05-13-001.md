### Step 2 — First extraction attempt failed (Windows libcairo missing)

`extract_content.py` imports `cairosvg` at module load. On Windows the native
`libcairo-2.dll` is not bundled with the `cairocffi` wheel, so the import raised
`OSError: no library called "cairo-2" was found`.

`cairosvg.svg2png` is only invoked when an SVG image is encountered during
extraction (see `extract_content.py` line 120 inside the SVG sanitization
helper). Since the source PPTX contains zero SVG parts, the function is never
called.

**Workaround:** wrote a thin runner (`changes/extract_runner.py`) that injects a
no-op `cairosvg` stub into `sys.modules` before invoking `extract_content.py`
via `runpy.run_path`. The stub's `svg2png` raises if ever called, so any future
SVG in source content would surface a clear error rather than silently corrupting
output.

The pipeline orchestrator `Invoke-PptxPipeline.ps1` does **not** expose
`--resolve-themes`, so the runner was invoked directly with the skill venv
Python rather than going through the orchestrator.

## Warnings and known issues

1. **`cairosvg` import requires native libcairo on Windows.** Worked around for
   this extraction by stubbing the module (no SVGs in source). If future source
   decks contain SVG, install the GTK runtime that provides `libcairo-2.dll`,
   or run the extraction on macOS / Linux.
2. **Slide 6 and slide 8 each contain three byte-identical PNG copies** of the
   same placeholder image (SHA1 `82D31D38…` for slide 6, `8D8C8C9A…` for slide
   8). The source deck pasted the same picture into all three concept columns.
   When authoring the new architecture deck, replace these placeholders with
   real concept diagrams or reference a single shared image.
3. **Theme font tokens `+mj-lt` and `+mn-lt` are not resolved by
   `--resolve-themes`.** That flag only resolves color references. Six element
   references retain the raw tokens. Before rebuild, decide on literal font
   substitutions — based on the rest of the deck the natural mapping is
   `+mj-lt → Segoe Sans Display` and `+mn-lt → Calibri`.
4. **Placeholder markers `_placeholder: true` appear on title placeholder
   textboxes** for every content slide. When rebuilding without `--template`
   these need to either be converted to plain textboxes or the rebuild needs to
   provide a template carrying matching layout names (`4_Title and Content`,
   `Title Only`, `Blank`).
5. **5 of 11 slides have no `speaker_notes:`** while `style.yaml` declares
   `speaker_notes_required: true`. Decide before rebuild whether to author
   missing notes for slides 2, 3, 4, 5, 8 or relax the default.
6. **Slide 6, 10, 11 have an empty top-level `title:` field** even though they
   carry a visible title placeholder. The extractor populates `title` only from
   explicit slide title shapes; for these slides the title text lives in a
   separate placeholder. Cosmetic only.
7. **Slide 10's value-driver table uses merged cells** (`merge_down: 3`,
   `_spanned: true`) that must be preserved exactly during any rebuild —
   `pptx_tables` supports this but the values are easy to drop in manual edits.
8. **Slide 1 cover image is 2.4 MB** with `crop: {l: 15562, r: 11767, b: 20161}`.
   Cropping metadata is preserved but the raw asset is large; consider
   re-exporting at slide resolution to shrink the new deck.
9. **Some paragraphs have empty `text: ''`** at the top of a paragraph list
   (e.g., slide 3 cards). These reproduce the spacing the source used; leave
   them in or replace with explicit `space_before`/`space_after` during edits.
